# AWCP 两种提供方式

2026-10-12：用户确认全站统一控制，第二种方式由 Desktop WebView 注入且网站不主动提供。已部署 `4b1410c-demo-site-20261012.3`；当前主动提供关闭，设置版本为 3。

## 实施

| 方式 | 网站职责 | Desktop 职责 |
| --- | --- | --- |
| 主动提供开启 | 自动提供当前页面的 AWCP 接口 | 可以使用网站提供的接口 |
| 主动提供关闭 | 普通网页，不创建网站 AWCP 入口；保留外部注入对象 | WebView 自行注入，并管理该接口及其生命周期 |

- Header 新增“主动提供 AWCP”开关，控制整个站点，产品名称继续使用 `demo-site`。
- SQLite 迁移 `005_awcp_settings.sql` 新增独立的单行设置表，初始 `activeEnabled=false`、`version=1`；服务重启、演示空间切换或重置不会重置该站点设置。
- `GET /api/v1/settings/awcp` 读取全站状态；`POST` 保存 `activeEnabled` 和 `expectedVersion`，检查允许的 Origin、有效演示 Cookie、当前 `X-Demo-Generation` 和设置版本。过期版本返回 409，不覆盖别人已保存的状态。
- `package/api` 维护有类型的 HTTP 合同，前端 service 处理加载、版本顺序、保存和失败重读；HTTP 响应丢失时重新读取后端状态，不假定写操作失败或成功。
- 读取状态前不创建网页全局入口；开启后提供现有 protocolVersion 1、manual、invoke、cancel 合同，按当前活动页面提供 Actions。关闭后撤销网站自己的入口与缓存引用，取消其在途请求；取消不回滚已提交业务。
- Desktop 已在网站之前注入时，主动提供关闭不覆盖它；网站原生接口开启后再关闭会恢复原来的 Desktop 接口；Desktop 在网站运行中替换接口时，网站关闭也不会删除后注入的对象。开关只表示网站主动提供状态，不根据 `window.awcp` 的存在推断 Desktop 注入是否开启。
- 业务页面及其私有注册上下文继续挂载，切换不重建表单或丢失草稿。关闭状态下普通浏览器页面不自动注入另一套接口。
- 可见页面每 15 秒读取设置，并在恢复焦点或可见状态时同步；此同步独立于“实时同步”三档开关。读取失败时撤销网站主动入口并显示重试，正常业务页面继续使用，保留已有外部注入接口。
- 当前为虚构演示站点：已有有效演示会话的访客可以切换全站状态。没有加入正式管理员身份体系，不扩展业务场景或修改依赖。
