## 实施结果

- MCP 实现版本更新为 0.3.0，默认完整授权从 32 个工具收敛为 11 个；可选重置仍为 2 个。精确目录见 [tools.json](../contracts/mcp/tools.json)，Scope 沿用原定义。
- `context_get` 包含场景支持目录与单步流转能力，移除单独的场景查询入口。
- `tasks_query` 通过 open／done 查询待办／已办，支持来源、关键词、北京时间日期和分页。total 是筛选后总数；汇总由客户端分页读取后计算。日期按待办截止日或已办完成日筛选。
- `records_query` 通过 kind 查询审批、差旅、费用；省略 id 为列表，指定 id 为单据详情。同一次 SQLite 读取包含任务、历史及需要的资料／附件选项，详情查询不允许混传列表筛选和分页参数。
- `workflow_transition` 通过 kind／action 执行一次明确状态流转。输入 Schema 和 Go service 共同限制合法动作，角色、Scope、generation、版本和幂等仍由领域服务执行。没有批量流转或任意设置状态的入口。
- `expense_prepare` 统一新费用核验保存与退回补正，不自动提交；提交和审批必须分别调用单步流转。`receipt_register` 只登记虚构票据元数据。
- 移除重复汇总、待办办理、单独已办查询及逐动作审批工具。完整报销、按日汇总等由基础工具多次调用完成。保留网页 HTTP 与 AWCP Action 合同，Action 映射显式记录参数和组合调用方式；未迁移 Action 不宣称存在对应工具。
- 生成器校验基础工具目录的数量、唯一名称及映射引用，MCP 测试校验实际发现结果，避免维护两份不一致的清单。

- 生成目录检查通过：31 场景、129 个既有业务 Action；计划引用、AWCP 合同和 Git whitespace 检查通过。
