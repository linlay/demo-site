- 修改前记录工作区状态（已有 111 条变更记录），沿用现有工作区并保留已有审批中心、全局身份、紧凑布局和风险入口变更；未变更依赖、未安装、未远程发布。
- 全站只开放林悦（EMP-001）和陈明（EMP-002）。林悦发起和经办现有流程；陈明执行所有已实现的审批节点，并访问独立数据分析页。账户菜单只显示这两类职责，跨页面、刷新与同空间标签页保持同一身份。
- 浏览器领域服务增加职责检查，保留原状态、角色、对象归属、版本、幂等和字段校验。客户适当性、研报、投行、风险、机构服务以及办公发起与审批均映射到这两位用户；不增加不存在的审批节点。机构服务的销售、研究和路演经办合并给林悦；既有预约参与人去重。
- 风险新事项可直接保存草稿或提交调查，首次保存时一起记录林悦为调查人，省去领取／分派步骤。界面明确显示林悦填报、陈明审批。账户编号、误报、阈值和市场字段使用业务文字。
- SQLite 迁移 `010_two_accounts.sql` 停用其余账户，转交未完成审批、差旅、报销及补正任务；归属发生变化时递增业务版本。已批准单据、审计与审批决定保留历史姓名，读取历史人员引用不要求其仍在职。新建空间和重置也使用双账户。
- 浏览器存储按空间／generation 保留，首次进入双账户配置时转交业务归属，保留草稿、事项状态和历史记录；后续加载不会重复转交。原协议与领域测试的默认十人 fixture 保留，实际应用与 session repository 明确使用双账户配置，新增测试直接覆盖实际配置。
- 当前页面新增 `demo.account.read` 与 `demo.account.switch`，AI 可读取两位账户的职责并切换全局身份；切换后重新读取 manual／revision。业务 Action 名称和 protocolVersion 1 合同不变，示例按两位账户改写，actorId 必须符合当前账户，领域服务继续执行职责校验。主动提供开关仍决定网站接口是否暴露。
