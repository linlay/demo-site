## 实施结果

- MCP 工具移除 `demo_` 前缀。默认完整授权提供 32 个工具，显式启用并授权重置后 34 个。工具列表仍根据真实 Scope 过滤；OAuth 无 scope 的默认值和认证发现提示改为完整业务范围，手动登录 Token 使用相同范围，旧／显式限制的令牌不自动扩权。
- 新增迁移 006：审批、资料关联、审批决定、差旅及同行人员、费用票据／明细、虚构附件元数据、业务待办、历史与幂等回执独立关系表。没有上传完整浏览器状态，也没有通过反射调用未迁移服务。
- O08 支持提交、批准、退回、撤回、重提，原申请人与指定同部门主管的角色边界、资料校验、业务版本和幂等检查保留。
- O09 支持差旅提交／批准／退回／重提、原有差旅草稿与附件关联保存、虚构票据登记、费用核验草稿、正式提交、审批、退回、补正和再提交。每张票据对应明细合计、申报总额、票据归属与跨报销重复使用均由后端检查；退回单没有当前版本核验则不能再次提交。
- O01 分页读取已迁移来源待办／已办，包含实际处理人、时间、结果和来源版本；提供总量／逾期汇总、北京时间按日汇总、差旅待办办理与来源导航。
- 状态、任务、审批决定、历史、幂等回执和 SSE 更新事件原子提交；失败全回滚，幂等重试不重复写事件。回执按空间、generation 和浏览器／OAuth 主体客户端隔离；重置清理全部本轮业务关系并恢复种子。
- 新 HTTP 业务入口与 MCP 共用 service，前端 `package/api` 和 typed service 对接。生产 O01/O08/O09 使用后端异步页面，原页面保留为独立协议测试／未迁移适配的基线；保持页面级 Action 名称和新申请 null 版本及待办当日／逾期来源类型的浏览器适配。
- 动态校验使用相同领域规则，但事务始终回滚，且不发布事件或消耗幂等键；取消不能撤销已提交业务。
- 分析默认查询实时业务；历史样本可单独选择，支持实时单据类型筛选和详情钻取。图表缓存和请求纳入 dataSource／kind，避免图表与汇总混用来源。金额按单据计数，差旅预算与报销可以分别筛选。
- 更新 OpenAPI、Action／工具映射和场景支持状态。修正目录生成器对 technicalFocus 字段的兼容，并强制保留 31 个场景，防止生成空目录。

## 范围边界

本轮不将其余 18 个办公／证券场景或 10 个浏览器协议实验标为后端已迁移。工作台只聚合 O08／O09 已迁移来源。旧浏览器本地办理数据未自动导入 SQLite，也不会伪装成 MCP 可办理记录。持久异步附件执行器、任务恢复、全场景国际化、24,000 条实时业务压测及远程部署未验收；历史样本大数据查询保留原有能力。

当前 11 工具版本使用相同业务 Scope，完整授权连接在更新服务后重新同步即可；旧 context:read Token 仅提供包含场景目录的 `context_get`，使用完整业务能力需重新授权。工具、Scope 与参数说明见 [连接文档](mcp-deployment.md)。
